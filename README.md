# 此刻（Cike）

一个本地优先的个人行动工作台：承接一次任务、长期项目、周期行动和学习复习。它要解决的不是“如何追赶截止日期”，而是：**当我现在有空时，可以做点什么？**

## 功能

- **三种任务生命周期**：一次完成后归档；周期行动按间隔再次出现；学习复习按掌握反馈调整间隔。
- **今日行动队列**：待做优先，同组内按建议日期、优先级和距离上次行动的时间排序。
- **行动动机**：可记录“为什么做”，分类完全由自己创建。
- **固定 AI 分析**：主动点击后，模型只返回“任务定义 / 建议下一步 / 节奏建议”三条简短内容，不自动创建任务、改变间隔或打卡。
- **可选记录**：打卡时可补充投入时长和备注；学习打卡使用“忘记 / 模糊 / 记得 / 轻松”四档反馈。
- **到期处理**：保留在队列，或真正顺延到明天。
- **历史统计**：累计打卡、投入时间、近七天图表与详细记录；一次任务的完成记录也会保留。
- **本地保存与备份**：无需账号，任务、分析和打卡保存在当前浏览器，可导出、导入 JSON 备份。
- **PWA 与响应式**：可安装，离线打开和本地打卡；适配桌面与手机。

## 本地开发

```bash
npm install
npm run dev
```

开发服务器默认运行在 `http://localhost:3000`。

## 构建与运行

```bash
npm run check
npm run test
npm run build
npm start
```

生产文件输出到 `dist/`：前端在 `dist/public/`，服务端入口为 `dist/boot.js`。PWA 的 Service Worker 只在生产构建中启用。

## AI 调用与降级

- AI 请求通过服务端 `POST /api/analyze` 发送，浏览器不接触模型密钥或网关地址。
- 可用模型在运行时读取，不写死具体模型名；系统提示词和输出约束位于 `api/routes/analyze.ts`，共享结构位于 `contracts/ai.ts`。
- 平台通过 `KIMI_AGENTGW_API_KEY` 和 `KIMI_AGENTGW_BASE_URL` 注入服务端配置；不要将密钥写入前端、JSON 备份或仓库。
- 模型调用可能消耗站点所有者的额度。失败时不自动重试，避免一次操作产生重复调用；用户可以明确点击重试。
- AI 是可选增强。接口不可用、超时、额度不足或离线时，创建、打卡、排序、历史与备份仍可使用。

## 数据与隐私

数据保存在浏览器的 `localStorage` 中，业务数据不写入云端数据库。清除站点数据、使用隐私模式或更换浏览器 / 设备前，请先在“设置”中导出备份。

只有主动点击“分析这件事”时，当前表单中的任务名称、行动动机、分类、任务类型和建议间隔才会由服务端发送给模型。不要在任务描述中填写密码、密钥或其他敏感信息。

当前备份版本为 2，导入时兼容版本 1 并补充默认值。导入是**整体覆盖**，不是合并；一次任务的 `completedAt` 决定其是否归档。

## 复习间隔

学习项目默认从短间隔开始。每次主动回忆后：

- 忘记：回到 1 天；
- 模糊：当前间隔约 × 1.25；
- 记得：当前间隔约 × 2；
- 轻松：当前间隔约 × 3。

这是一种轻量、可解释的启发式规则，并不声称对所有人或所有材料都存在唯一的“最佳间隔”。AI 的节奏建议不会直接改写这套调度规则。

## 通知限制

应用没有远程推送服务器。浏览器或应用完全关闭后，不能保证系统通知准时弹出；应用会在下次打开时补显示待做项目。

## 主要修改入口

- `src/types/index.ts`：任务、分析和本地备份结构。
- `src/lib/scheduler.ts`：一次任务归档、复习间隔、日期和推荐排序。
- `src/hooks/useLocalData.ts`：版本迁移、导入校验和本地持久化。
- `src/components/ItemDialog.tsx`：任务输入、AI 请求和固定分析预览。
- `src/components/ItemRow.tsx`：任务及 AI 分析的固定展示位置。
- `api/routes/analyze.ts`：系统提示词、模型调用和错误降级。
- `contracts/ai.ts`：AI 输入与三项结构化输出的约束。
